The skill stack: exactly one pick per task

There are thousands of Claude Code skills, and most of them are noise or overlap. This is a curated stack: for each job in a product build, one skill, plugin or connector, why it won, and what it replaces so you don't install duplicates.

How picks were chosen

Official or vendor-maintained first (Anthropic, GitHub, Vercel, Supabase, LangChain, Trail of Bits), then the most-adopted community sets (Superpowers, Matt Pocock, Dean Peters). Two skills that give conflicting instructions for the same job confuse Claude, so each task has one owner. Skills load on demand, so a lean set costs little context; MCP servers cost more, so add those per project.

Skills vs plugins vs MCP in one minute

Skill

A folder with SKILL.md (+ optional scripts and references). Claude loads it only when the task matches its description. Lives in .claude/skills/ (project) or ~/.claude/skills/ (you). Teaches how.

Plugin

An installable bundle of skills, commands, subagents, hooks and/or MCP servers from a marketplace. claude-plugins-official is built in.

MCP server

A connector that gives Claude tools and live data: your database, GitHub, Figma, a browser. See MCP & connectors.

Built-in

Already in Claude Code: /review, /security-review, plan mode, web search, subagents. Don't install a skill for something built in.

What we deliberately left out (and why)

Popular optionWhy it's not in the core stack
Full Superpowers pluginExcellent, but its brainstorming → writing-plans → executing-plans chain overlaps with Spec Kit. We take only its TDD and debugging skills. If you prefer Superpowers' flow, use it instead of Spec Kit, not with it.
feature-dev pluginA guided feature workflow (clarify → explore → architect → implement → review). Same job as Spec Kit; pick one.
pr-review-toolkitSix parallel review agents; great for big PRs but heavier. code-review + /review covers prototypes and most PRs.
phuryn/pm-skills, Matt Pocock's to-prdBoth write PRDs. We use Dean Peters' prd-development as the single PRD owner; it's PM-first and comes from a 70-skill PM library you can pull more from.
Trail of Bits skillsProfessional-grade audits (CodeQL, Semgrep, variant analysis). Add when you have a real product handling money or sensitive data, not for prototypes.
Exa / Tavily / Brave MCPFirecrawl covers search + scrape; Claude Code also has built-in web search. Add Exa only if you need semantic discovery at scale.
"1,000+ skills" mega-bundlesConflicting instructions and unknown authors. Install skills individually, from sources you trust, and read the SKILL.md first.
Security note

Skills can include scripts, and MCP servers can read and act on your data. Prefer official or well-known sources, read SKILL.md before installing, give MCP servers the least access they need, and never paste production keys into a session.

When to write your own skill

When you've explained the same thing to Claude three times: your PRD format, your company's design system, how your team writes tickets, your demo script. Run the skill-creator skill ("help me create a skill for…"); it scaffolds the folder, writes a description that triggers at the right time, and can test it. Keep each skill to one job with a sharp description.
