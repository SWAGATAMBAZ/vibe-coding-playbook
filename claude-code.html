Claude Code essentials

Claude Code is an agent in your terminal (and IDE, desktop and web) that reads your repo, runs commands, edits files and verifies its work. This page is the mental model plus the 20% of features that do 80% of the work.

The mental model

Gather contextread files, search, docs via MCP
→
Planplan mode, spec, tasks
→
Actedit, run, call tools
→
Verifytests, browser, lint
↺

Everything you configure feeds one of those boxes. Quality comes from better context (CLAUDE.md, specs, MCP docs), better plans (plan mode, spec-driven flow) and forced verification (tests, hooks, Playwright). Treat Claude like a very fast engineer with no memory: give it a clear brief and a way to check its own work.

Install & first session

The npm package @anthropic-ai/claude-code is deprecated in favour of the native installer. Claude Code also runs in VS Code/JetBrains, the desktop app and on the web, with the same configuration files.

CLAUDE.md: the project's memory

A markdown file Claude reads at the start of every session. Put the non-obvious things there: commands, conventions, architecture, gotchas. Keep it short (under ~150 lines); it's advisory, so anything that must always happen belongs in a hook.

LocationScopeUse for
~/.claude/CLAUDE.mdYou, every projectPersonal preferences: "explain trade-offs", "use pnpm", "never commit to main".
./CLAUDE.md (committed)Team, this repoStack, commands, conventions, architecture, definition of done.
./sub/dir/CLAUDE.mdThat folderRules specific to e.g. /api or /web.

A ready-made template is on the Starter kit page. Use @path/to/file.md inside CLAUDE.md to import longer docs (e.g. your spec) instead of pasting them.

Plan mode & permission modes

  • Shift+Tab cycles modes: normal (asks before edits), auto-accept edits, and plan mode (read-only: it researches and proposes, can't change files).
  • Always plan first for anything bigger than a one-file change. Approve or edit the plan, then let it execute.
  • Esc interrupts; Esc Esc (or /rewind) jumps back to an earlier point and can restore code.
  • Pre-approve safe commands in .claude/settings.json (permissions.allow) so you're not clicking "yes" 40 times, and deny dangerous ones.

🎯 Interview one-liner

"CLAUDE.md is advisory context; hooks are guaranteed. Skills load on demand, so I can have many without bloating context; MCP gives the agent tools and live data; subagents isolate context for specialist work."

Context hygiene: the hidden skill

  • One task per session. /clear when switching.
  • Point at files with @ instead of letting it search the whole repo.
  • Install only the MCP servers a project needs (project scope), because every server's tool list costs context.
  • For long tasks: keep a PLAN.md/tasks.md checklist, let Claude tick it, and restart sessions from it.
  • Delegate research and review to subagents so their reading doesn't fill your main window.

Subagents & parallel work

Run two approaches in parallel with git worktrees (each agent gets an isolated copy), then keep the better one. Great for "try two UI directions".

Headless & CI

Ten habits of strong Claude Code users

  1. Plan mode before any multi-file change.
  2. Give acceptance criteria, not just a goal.
  3. Make it verify: tests, a browser check, or a command whose output proves success.
  4. Commit after every working step, so rollback is cheap.
  5. Small prompts, one feature at a time.
  6. Ask for root cause before a fix.
  7. Read the diff. Every time.
  8. Keep CLAUDE.md short and current; delete stale rules.
  9. Encode anything you repeat 3 times as a command or skill.
  10. Run /review and /security-review before you demo or merge.
