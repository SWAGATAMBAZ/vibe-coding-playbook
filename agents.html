AI agents: when, which framework, and how to build one

Most "agent" ideas should be workflows. This page helps you tell the difference, pick n8n vs LangGraph vs the Claude Agent SDK, and vibe code a real agent with tools, memory and human approval.

Workflow or agent?

Workflow

Code decides the path

LLM calls are steps in a fixed pipeline: classify → extract → route → notify. Predictable, cheap, testable. Use by default.

Agent

The model decides the path

An LLM in a loop chooses tools until the goal is met. Flexible for open-ended tasks, but costlier, slower and harder to test. Use when steps can't be known in advance.

🎯 The line that impresses

"I'd start with the simplest thing that works: a single LLM call with retrieval, then a workflow. I'd only make it an agent if the steps genuinely vary per request, and I'd add human approval before any action that's hard to undo."

Rule of thumb

Ops automation → n8n. Custom product feature with state and approvals → LangGraph. Agent that needs to read/write files, run tools, use MCP, and you're on Claude → Claude Agent SDK. Prototype in whichever you can explain best in the interview.

Building with n8n

  1. Run n8n: n8n Cloud, or self-host with Docker (docker run -it -p 5678:5678 n8nio/n8n).
  2. Trigger: Webhook, Schedule, Gmail/Slack/Form trigger.
  3. AI Agent node: attach a Chat Model (Claude/OpenAI), Memory (window buffer or Postgres), and Tools (HTTP Request, Postgres, Google Sheets, Slack, or a sub-workflow as a tool).
  4. Structured output parser to get JSON you can route on with an IF/Switch node.
  5. Human in the loop: send to Slack/email with approve/reject, wait for the response, then act.
  6. Error workflow for failures; log runs; test with pinned data before activating.

Memory, multi-agent and protocols

  • Short-term memory: the conversation/thread state (checkpointer).
  • Long-term memory: facts and preferences stored in your DB (or a store) and retrieved per user. Let users see and delete it.
  • Multi-agent: split by context and permissions, not by job titles. One orchestrator + specialised workers usually beats a "team" of chatty agents.
  • MCP connects an agent to tools; A2A (agent-to-agent) lets agents from different systems talk. Name both if asked about interoperability.

Guardrails & evals for agents

Least privilege

Only the tools needed; read-only by default; scoped credentials.

Human approval

Before sending, paying, deleting or anything external and irreversible.

Budgets

Max steps, max tokens, max cost per run; timeouts.

Prompt-injection defence

Treat tool/web content as data; separate instructions; validate tool arguments.

Tracing

Every step, tool call and cost logged (LangSmith, Langfuse).

Evals

Task success rate, tool-call accuracy, steps per task, cost per task, human-escalation rate, on a fixed test set.
