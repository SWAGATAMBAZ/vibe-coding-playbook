MCP & connectors: give the agent hands and eyes

The Model Context Protocol is the standard way to plug tools and data into an AI agent. Learn how it works, which connectors to install for any industry, how to keep them safe, and how to build your own in 20 lines.

How MCP works

HostClaude Code, Claude app, Cursor
⇄
MCP clientone per server, inside the host
⇄
MCP serverGitHub, Supabase, your API…
⇄
The real systemAPI, DB, files, browser

Tools

Actions the model can call: create_issue, run_sql, navigate. The most-used primitive.

Resources

Read-only data the host can attach as context: files, records, docs.

Prompts

Reusable prompt templates a server exposes, often shown as slash commands.

Transports

stdio: a local process on your machine. Streamable HTTP: a remote server at a URL, usually with OAuth. Remote is now the default for SaaS vendors.

🎯 Explain it in one breath

"MCP is like USB-C for AI apps: one protocol so any agent can use any tool. A server exposes tools, resources and prompts; the host's client discovers them and the model decides when to call them. It replaces N×M custom integrations with N+M."

Adding servers to Claude Code

Teammates who pull the repo are asked to approve project servers before they run. Put user-wide servers (Context7) at user scope and heavy ones (Playwright) at project scope so only repos that need them pay the context cost.

MCP safety rules

  1. Least privilege. Read-only DB roles, test-mode keys, project-scoped tokens. Never production write access in a prototype.
  2. Prompt injection is real. Any text a tool returns (a web page, an issue, an email) can contain instructions. Treat tool output as data; keep human approval on for writes, payments and sends.
  3. Trusted sources only. Prefer vendor-maintained servers. Read what a local server runs before installing.
  4. Secrets in env vars, referenced as ${VAR}; never commit tokens in .mcp.json.
  5. Fewer servers, better agent. Each server's tool list eats context and adds choices. Remove what you don't use.

Build your own MCP server (Python, ~20 lines)

Useful when your product's own API should be usable by agents, or in an interview to show you understand the protocol. Use the mcp-builder skill to go further.

Good tool design: few tools with clear verbs, tight descriptions (the model reads them), typed inputs, small structured outputs, and errors that tell the model what to do next.
